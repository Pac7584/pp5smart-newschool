# มอบหมายงานและสิทธิ์ครู

ส่วนนี้ต้องทดลองในโรงเรียนทดสอบก่อนเปิดใช้กับโรงเรียนจริง การติดตั้ง SQL เพียงอย่างเดียวยังไม่เปิดการจำกัดสิทธิ์ใหม่ ผู้ดูแลต้องตรวจการมอบหมาย แล้วเปิดใช้ด้วยตนเอง

## ใครทำอะไรได้

| บัญชี | ขอบเขตเมื่อเปิดใช้ |
|---|---|
| ผู้ดูแลระบบ | ทุกห้อง ทุกวิชา จัดการบัญชี การมอบหมาย และตั้งค่ากลาง |
| ครูประจำชั้น | ห้องและปีที่มอบหมาย: คะแนนทุกวิชา เวลาเรียน ประเมิน สุขภาพ พฤติกรรม ความเห็น และรายงาน ปพ.5/ปพ.6 |
| ครูประจำวิชา | วิชา ห้อง ปี และภาคที่มอบหมาย: รายชื่อที่จำเป็น คะแนน และรายงานรายวิชา ไม่ได้รับข้อมูลครอบครัว สุขภาพ หรือรูปนักเรียน |
| ผู้ปกครอง | นักเรียนที่ผู้ดูแลเชื่อมให้ ตามสิทธิ์เดิมของหน้าผู้ปกครอง |

ครูคนเดียวรับหลายห้องและหลายวิชาได้ เป็นครูประจำชั้นห้องหนึ่งและครูประจำวิชาอีกห้องหนึ่งได้ การมอบหมายผูกกับ ID บัญชีจริง ไม่เดาจากชื่อครูบนเอกสาร การเปิด/ปิดลำดับและลายน้ำยังเลือกตอนพิมพ์แต่ละครั้ง ไม่ใช่การแก้ตั้งค่ากลาง และไม่ใช่ค่าที่บันทึกถาวรแยกห้อง

เมื่อเปิดใช้สิทธิ์ตามการมอบหมาย ครูที่มีห้องเดียวในชั้นที่เลือกจะได้ห้องนั้นเป็นค่าเริ่มต้น และหน้าที่ใช้ช่องเลือกชั้น/ห้องจะโหลดรายชื่อผ่านตัวโหลดเดิมทันที รอให้ตัวเลือกห้องโหลดเสร็จก่อน ไม่ยึดห้องที่จำค้างจากบัญชีอื่น ครูที่ได้รับหลายห้องยังสลับห้องที่ได้รับมอบหมายได้ การเลือกภาคเรียนและรายวิชายังคงใช้ตัวเลือกของแต่ละหน้า

หน้า ปพ.6 ปกติและแบบมีคะแนนใช้ปุ่มห้องแทนช่องเลือก เมื่อครูมีงานประจำชั้นห้องเดียวในปีที่เลือก ระบบจะเลือกปุ่มห้องนั้นและแสดงรายชื่อทันทีหลังโหลดข้อมูล การเปลี่ยนปีจะตรวจงานของปีนั้นใหม่ และชื่อครูจะอ่านตามปีที่เลือก ครูที่มีหลายห้องยังเลือกห้องเอง ระบบไม่กดเลือกห้องซ้ำขณะเลือกนักเรียนหรือปรับรูปแบบรายงาน

## ติดตั้งบนโรงเรียนทดสอบ

1. สำรองข้อมูลโรงเรียนทดสอบก่อน ผู้ดูแลเป็นผู้กดสำรองเอง
2. โรงเรียนที่มีฐานข้อมูลแล้ว ใช้ Supabase SQL Editor รันเฉพาะ [202610110027_teacher_scope.sql](../supabase/migrations/202610110027_teacher_scope.sql) ไม่รัน install.sql ทับฐานเดิม
3. SQL นี้ต้องมีโครงสร้างล่าสุดก่อนหน้า รวมถึง student_year_rosters และ subjects.semester หากฐานเก่ากว่านี้ให้หยุดตรวจรุ่นก่อน ไม่ข้ามข้อความผิดพลาด
4. เปิดเว็บรุ่นใหม่ เข้าด้วยผู้ดูแล แล้วเปิด **ตั้งค่าและดูแลระบบ → มอบหมายงานและสิทธิ์ครู** ถ้า SQL ยังไม่พร้อม หน้าเว็บจะบอกให้ติดตั้ง
5. สร้างบัญชีครูในหน้าจัดการผู้ใช้ ผู้ดูแลพิมพ์อีเมลและรหัสผ่านเอง ไม่ส่งรหัสผ่านให้ผู้ช่วย
6. เลือกปีและบัญชีครู เพิ่มครูประจำชั้น ป.3/1 แล้วกด **บันทึกการมอบหมาย** ถ้าทดสอบครูประจำวิชา ให้ใช้บัญชีอีกคนและเลือกวิชา ห้อง และภาคจริง
7. ตรวจงานของครูที่เปิดใช้งานทุกคนก่อน บัญชีเก่าที่มี user_id หรือห้องใน user_profiles จะถูกนำมาตั้งต้นเพียงครั้งเดียว ต้องตรวจทาน ไม่ถือว่าเป็นการรับรองสิทธิ์ถูกต้องแล้ว
8. เมื่อครูทุกคนมีงานในปีปัจจุบัน พิมพ์ **ENABLE_TEACHER_SCOPE** แล้วกดเปิดใช้ ระบบจะปฏิเสธหากยังมีครูไม่มีงาน หรือปีปัจจุบันปิด/ล็อกอยู่

ระหว่างยังไม่เปิดใช้ ระบบยังคงสิทธิ์ครูแบบเดิม อย่าเข้าใจว่าการเห็นเมนูการมอบหมายแปลว่าฐานข้อมูลจำกัดสิทธิ์แล้ว ต้องเห็นข้อความ **เปิดใช้สิทธิ์ตามการมอบหมายแล้ว** ด้วย

## ทดสอบทีละหน้าจอ

ผู้ดูแลดำเนินการบนเว็บ ส่งภาพหน้าจอทุกขั้นโดยไม่ให้เห็นรหัสผ่าน ผู้ช่วยไม่เขียนฐานข้อมูลโดยตรง

1. บัญชีผู้ดูแล: ภาพรายงานการมอบหมายที่บันทึกและเปิดใช้แล้ว
2. ออกจากระบบ เข้าบัญชีครูประจำชั้น ป.3/1: ตรวจเมนู ไม่มีตั้งค่ากลาง จัดการผู้ใช้ หรือมอบหมายสิทธิ์
3. รายชื่อนักเรียน: เห็นเฉพาะห้องที่ได้รับมอบหมาย ไม่เห็น ม.1/1
4. เวลาเรียนและคะแนน: เปิดและบันทึกข้อมูลทดสอบของ ป.3/1 ได้ เลือกข้อมูลที่จะเปลี่ยนและคืนค่าร่วมกันก่อน
5. ปพ.5/ปพ.6: พิมพ์ของห้องตนเองได้ ทดลองเปิด/ปิดลำดับและลายน้ำ ให้ตรวจ PDF จริงด้วย
6. ทดสอบลิงก์ตรงไปหน้าผู้ดูแลและหน้ารายงานของห้องอื่น ต้องไม่เปิดข้อมูล รวมถึงลอง ID นักเรียนต่างห้อง ไม่ใช้การซ่อนเมนูเป็นหลักฐานเพียงอย่างเดียว
7. บัญชีครูประจำวิชา: เห็นรายชื่อและคะแนนเฉพาะวิชาที่มอบหมายในหลายห้อง ไม่เห็นข้อมูลส่วนตัวเต็ม เวลาเรียน ความเห็น หรือ ปพ.6 ของห้องที่ไม่ได้เป็นครูประจำชั้น
8. วิชามัธยม: ภาคที่มอบหมายต้องตรงรายวิชา ไม่สามารถบันทึกคะแนนอีกภาคหรือวิชาอื่นได้
9. ปีเก่า: ต้องมีงานที่มอบหมายในปีนั้นจึงอ่านได้ เมื่อปีปิด/ล็อก ครูต้องแก้คะแนนไม่ได้
10. ผู้ดูแลยังดูทุกห้องได้ ผู้ปกครองยังเห็นเฉพาะบุตรที่เชื่อมไว้ บัญชีครูปิดใช้งานต้องเข้าไม่ได้

บันทึกผ่าน/ไม่ผ่านพร้อมภาพจริง อย่าใช้ผลทดสอบจำลองแทนการทดสอบบัญชีจริง

## เปลี่ยนปีและถอนงาน

การมอบหมายแยกปี ไม่ต่อสิทธิ์ข้ามปีอัตโนมัติ ก่อนเปลี่ยนปีให้ผู้ดูแลเตรียมงานของปีใหม่ หากถอนงานทั้งหมดของครูในปีปัจจุบันหลังเปิดใช้ ให้ปิดใช้งานบัญชีครูก่อน หรือมอบหมายงานที่ถูกต้องแทน ระบบจะไม่ยอมบันทึกรายการว่างให้ครูที่ยังเปิดใช้งาน

สำรองเต็มเว็บจะรวม teacher_access_assignments และ teacher_scope_settings เมื่อติดตั้งส่วนนี้แล้ว สำรองรายปีจะรวมการมอบหมายเฉพาะปีที่เลือก ไม่รวมสวิตช์ส่วนกลาง ทั้งสองอย่างเป็นการอ่าน/เปรียบเทียบ ไม่ใช่การนำเข้าสิทธิ์หรือกู้คืนบัญชีอัตโนมัติ

## ย้อนกลับกรณีจำเป็น

เจ้าของฐานข้อมูลรัน [202610110027_teacher_scope_rollback.sql](../supabase/rollbacks/202610110027_teacher_scope_rollback.sql) เอง แล้วออก/เข้าเว็บใหม่ SQL นี้ปิดการจำกัดสิทธิ์ใหม่และกลับไปใช้สิทธิ์ครูแบบเดิมที่กว้างกว่า ไม่ลบการมอบหมาย นักเรียน หรือคะแนน และไม่คืนค่าคะแนนที่แก้ไปแล้ว จึงต้องตัดสินใจโดยผู้ดูแล

## เปิดใช้กับโรงเรียนจริง

ทำหลังการทดสอบบัญชีจริงในโรงเรียนทดสอบผ่านแล้วเท่านั้น ส่งรุ่นเว็บตามกระบวนการปกติ เจ้าของรัน SQL บนโรงเรียนจริง ตรวจ ID และงานของครูทุกคน แล้วเปิดใช้ ไม่ถือว่าการ push เว็บเป็นการติดตั้ง SQL หรือเปิดใช้สิทธิ์ฐานข้อมูล
